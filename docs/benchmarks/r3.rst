R3 benchmark results
====================

This page reports the R3 benchmark measurements. Results are generated by the
harness described in :doc:`harness` and stored under
``benchmarks/results/r3/``.

The numbers below come from a real release-mode run of the harness
(100 000 rows, 3 iterations per step, ``report-100K-r3.md``). A missing
measurement is preferred over a fabricated one — nothing here is aspirational.

What the R3 benchmark does and does not show
--------------------------------------------

* The R3 benchmarks measure the current **transitional** architecture: a WAL
  authority with a page store rebuilt from recovered state. Fetch fixes that
  reflect the final checkpointed architecture are therefore not yet measured.
* No benchmark in this phase claims billion-row capability. That claim is
  explicitly deferred and would require the R6 qualification path with the
  final storage lifecycle.
* Aggregation / GROUP BY run through the batch aggregate pipeline (R3-EXEC-1);
  JOIN runs through the batch hash join pipeline (R3-EXEC-2) with both inputs
  materialized from persistent storage. Aggregate, join, and ORDER BY inputs
  are held in RAM — external spill is deferred.
